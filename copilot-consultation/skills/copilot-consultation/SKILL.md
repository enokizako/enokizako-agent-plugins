# GitHub Copilot CLIとの相談

相談先（GitHub Copilot CLI）にセカンドオピニオンを求め、その回答を自分の見解と照らし合わせてユーザーに報告する。ユーザーはCopilotの生出力を読まない。

## 1. Copilot CLIの確認

`copilot` コマンドが無ければ、インストールされていない事をユーザーに伝えて終える。インストールや認証を代わりに行わない。

## 2. 相談の深さ

ユーザーが深さを指定していない時（「軽く」「よく」「全力で」等が無い時）は、次の3つから選んでもらう。

| 深さ                     | 往復                                       | 自分の仮見解をプロンプトに含めるか                                         |
| ------------------------ | ------------------------------------------ | -------------------------------------------------------------------------- |
| **よく相談する**（推奨） | 必要に応じて2往復                          | 自分で判断する                                                             |
| **全力で深く相談する**   | 2往復を原則とし、明らかに不要な時だけ省く  | 必ず含める。検討したが採用しない事も、その理由と共に書き、検証を求める     |
| **軽く相談する**         | 1往復                                      | 自分で判断する                                                             |

## 3. プロンプト

会話から、今何を相談すべきかを決める。ユーザーがテーマを指定していればそれに従う。

プロンプトには次を含める。

1. プロジェクトの背景（簡潔に）
2. 相談したい具体的な内容
3. 自分の仮見解（深さの表に従う）。現時点の見解と理由、検討したが採用しない事とその理由を書く。検討していない事を、採用しない事として書かない
4. 指定した観点は出発点であり、リポジトリを自分で探索して、気になる点は観点の外でも報告してほしいという依頼。これは常に含める
5. ファイルを変更しないでほしいという依頼

出力量を制限しない。制限すると重要な指摘が落ちる。

## 4. 実行

### 実行時の注意

- 非対話モードで実行する。プロンプトは作業ツリーの外の一時ファイルに書き、stdinから渡す。作業ツリーの中に置くと、未commitの変更としてレビュー対象に混ざる
- 非対話モードでは、許可されていないツールの利用は確認されずに拒否される。読むためのツールとshellは許可し、ファイルの書き込みは拒否する。拒否のルールは許可のルールより優先される。`gh` 等の外部通信が要る相談では、それも許可する
- Copilotの質問フォーム（ask_user）を無効にする。非対話モードでは答える人がいない
- 回答だけを標準出力に出すモードで実行する。このモードでは使ったmodelが出力に出ないので、使用量をJSONファイルに書き出させ、そこからmodelを読む
- 2往復目のために、1往復目はセッションIDを自分で生成したUUIDに固定して始める。2往復目はそのIDでセッションを再開するので、1往復目の文脈を送り直さなくてよい
- ユーザーがmodelやreasoning effortを指定した時は、それぞれのオプションで上書きする。指定が無ければ上書きしない。modelは表示名ではなくIDで渡す。IDが分からなければ、Copilot CLIのhelpや設定から調べる
- Bashツールのtimeoutは15分にする
- 細かいオプションは `copilot --help` と `copilot help permissions` で確かめる

### 実行後の確認

- 作業ツリーに変更が無い事を確かめる。変更があれば、元に戻さずにユーザーに報告する
- 回答の中に、コマンドの失敗や権限の拒否で情報を得られなかった兆候が無いか確かめる。あれば、そのコマンドを自分で実行して正しい情報を得て、その情報が無かったために外れた指摘を特定する

### 2往復目

「よく」では、次のどれかに当たる時に2往復目を行う。

- 深掘りすべき重要な点がCopilotの指摘にある
- Copilotの指摘に、反論や補完をしたい
- 探索が足りない領域がある

2往復目のプロンプトには、Copilotの回答に対する自分の反論・補完・追加質問と、さらに掘り下げてほしい観点を書く。往復は2回までとし、3回目はユーザーに確かめてから行う。

## 5. 報告

次の構成で報告する。見出しの「Claude Code」は、自分のAgent名にする。

### Copilotへの相談内容

`GitHub Copilot CLI 1.0.114（Claude Sonnet 5.5, reasoning effort: high）` の形で実行環境を1行書く。versionはCLIから、modelは使用量のJSONから取る。reasoning effortは指定した時だけ書く。続けて、送ったプロンプトの概要を1〜2文で書く。

Copilotのmodelが自分と同じ系列の時は、その事を書く。同じ系列のmodelでは、見落としも重なりやすい。

### Copilotの回答の要約

主な指摘と提案を箇条書きにする。

### Claude Codeの見解

- 同意する指摘
- 異なる意見を持つ指摘と、その理由
- Copilotが見落としていると考える点
- 2往復目を行った時は、その理由と、明らかになった事

Copilotの指摘をそのまま受け入れない。自分で確かめてから報告する。食い違いは、両方の理由を書いてユーザーが判断できるようにする。

### 次のアクションの提案

ユーザーが決めるべき事と、推奨する次の一手を書く。

回答が長すぎて要約しきれない時は、その事と、読めた範囲の概要を伝え、観点を絞って再実行するか等をユーザーと相談する。

Copilotの失敗に繰り返しのパターンを見つけた時は、次回からの改善策をユーザーに提案する。
